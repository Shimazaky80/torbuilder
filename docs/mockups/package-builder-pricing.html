How seasons work — the answer to your one challenge
  • A season is a header, not a copy. Stored as { from, to, accommodation, single_supplement } — it points at the same service rows. Nothing duplicates, no service reload.
  • Two price stores. The vehicle × traveller grid is annual and written once. The season overlay holds only the two numbers your Excel proves vary.
  • Resolve by date. Trip dates → the season containing them → accommodation from that season, everything else from the annual pool.
  • Straddling a boundary → highest rate wins (decision A), charged for all nights, never split.
  • Prices are a locked snapshot (decision E). Library edits never move an existing package; the user pulls them in deliberately.
  • A column is a vehicle size (decision F). Two suppliers with the same 30-seater are one size and one column — the cheaper one is picked at the service line.
